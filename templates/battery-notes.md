# 题库编写规矩（battery.json 格式：[{"q": 说法, "gold": skill名或none, "kind": "pos|neg"}]）

1. 每 skill 3 条正例：按真实使用场景写口语化说法，**刻意不照抄描述里的词**（抄词测的是关键词匹配，不是触发）。
2. **gold 必须读过该 skill 的真实内容才能标**（SKILL.md 本体、README、子目录结构）。凭名称/常识推断的 gold 必须在条目上加 "gold_basis": "inferred"，且这类条目**不许计入头条分数**——2026-10-19 punk-skill 事件：描述与 gold 同按错误推断写成、互相对出 3/3 假成绩（真身是视觉生成、被当成 X 起号 playbook）。
3. 邻近题：同域 skill 之间互设防抢题（如单张封面 vs 成套卡片），改完一条描述必须连带跑邻居的题。
4. 全局负例 10 条：天气、翻译、订票、数学题、闲聊等与任何 skill 无关的请求，标准答案 none，验乱触发。
5. 题库变更与目录变更要在报告里分开记账：哪轮改了题、哪轮改了描述，不然分数不可比。
